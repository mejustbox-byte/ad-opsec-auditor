# Требования GITHUB-OPSEC: Microsoft AD

Статус: требования продукта и MVP, 2026-10-09. Пользователь разрешил реализацию, commit/push, PR, merge и предварительный выпуск. Владелец AD утверждает область и доступ; проверяющий безопасности — правила; оператор выполняет сбор; владелец восстановления подтверждает процедуры.

## Цель и границы

Воспроизводимая оценка заявленных конфигурационных свидетельств AD и их ограничений. Только чтение, без эксплуатации, исправления инфраструктуры и получения секретов. В области: Tier 0, AD CS, ACL/делегирование, сервисные учётные записи, NTLM/LDAP/SMB, журналирование, восстановление леса. Entra ID, эксплуатация CVE, парольный аудит и резервное копирование самим аудитором вне области.

Linux используется для разработки и синтетических примеров. Реальный сбор требует отдельного Windows-стенда; рабочий лес не является тестовым. MVP — автономный анализ нормализованных фактов оператора, а не выполнение будущего сбора.

## Нефункциональные требования

NFR-01: недоверенный ввод, версия схемы, ограничения размера/глубины/объектов, безопасный разбор. NFR-02: минимальные права по источнику, без Domain Admin по умолчанию; дополнительные права чтения документируются. NFR-03: будущий сбор ограничивает страницы и нагрузку; начальные параметры — один запрос, 30 секунд, 1000 объектов на страницу, с уточнением по стенду. NFR-04: проверка TLS, подписей и хешей не отключается. NFR-05: реальные данные/отчёты в частном хранилище с ACL, шифрованием и согласованным удалением (для стенда 7 дней). NFR-06: нет credentials, private keys, tickets и полного содержимого событий в отчётах. NFR-07: стабильные ID, версия правил и связь с матрицей.

## Семантика и MVP

Статусы MVP: pass/fail/unknown/not_run. Pass требует всех обязательных фактов, complete покрытия и существующих evidence_refs; это соответствие правилам по заявленным данным, не проверка истинности источника. Unknown — недостаток данных, not_run — отсутствие наблюдения. not_applicable отложен; исключение не становится pass. Критичность отделена от уверенности; исключения требуют владельца, срока и обоснования.

MVP-01: CLI validate/audit/schema, JSON и безопасный Markdown. MVP-02: нормализованные факты, без собственного сбора и вычисления полного графа ACL. MVP-03: вход ≤2 MiB, глубина ≤16, неизвестные поля/duplicate keys/non-finite numbers запрещены. MVP-04: повреждённые ссылки и противоречивые состояния отвергаются. MVP-05: SHA256 точных байтов, версии, предупреждение о непроверенном происхождении. MVP-06: ошибки дают exit 2 без traceback и вывода входных значений; файлы не перезаписываются. MVP-07: Python 3.12 без зависимостей во время работы, закреплённая сборка и проверка установки. MVP-08: предварительный выпуск не закрывает Windows-стенд. MVP-09: вся пользовательская документация/помощь/описания на русском; ключи, команды, пути и ID сохранены.

Приёмка MVP: содержательные модульные/CLI тесты, отрицательные случаи, сверка схемы, установка артефактов, повторяемость и CI. Приёмка будущего сборщика: отдельные Windows-свидетельства и проверка операций только чтения. См. [план](mvp-plan.md).
