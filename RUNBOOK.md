# Эксплуатация автономного анализатора

## Обычный запуск

Установить по [INSTALL](INSTALL.md); проверить версию и validate. Частный снимок должен быть подготовлен доверенным оператором в согласованной области. На Linux использовать частный каталог с owner-only правами, на Windows утверждённый ACL и шифрование диска. CLI не настраивает шифрование или права родителя.

`ad-opsec-auditor audit PRIVATE_INPUT --format json --output NEW_PRIVATE_REPORT`. Вход ≤2 MiB, обычный локальный файл. Новый отчёт POSIX 0600; вывод в stdout защищать отдельно. Не загружать частные данные в Git/Actions/этот cloud workspace. Для лаборатории срок удаления 7 дней либо утверждённый владельцем иной срок.

## Интерпретация и ошибки

Pass ограничен фактами/областью; fail — риск по правилу, не доказательство эксплуатации; unknown — недостаток данных; not_run — отсутствие наблюдения. Exit 1/3 является результатом аудита, не сбоем команды. Exit 2: проверить формат/размер/типы/дубли/UTC/ссылки, существование входа, новый доступный output. Содержимое неверных данных не выводится; для отладки использовать минимальный синтетический пример.

При partial/unknown уточнить доступ и полноту источника, не заменять неизвестное на zero/false. Для существующего output выбрать новое имя после проверки владельца, не удалять чужой файл. Symlink/директория не являются допустимым output. Реальные контрольные запросы AD выполняются только на [стенде](LOCAL-PC.md).

## Обновление и инцидент

Обновлять отдельный venv после проверки tag/commit/SHA256 и изменения контракта. Сохранять старые частные отчёты с версией/хешем; не сравнивать свободный русский текст как машинный ID. При утечке остановить публикацию, ограничить доступ и отозвать credential через владельца; очистка истории отдельным согласованным процессом. Не печатать секрет в issue.

Службы, фоновые процессы, БД, backups или automatic restore у CLI отсутствуют. Остановка — завершение процесса; он не менял AD. Удаление пакета не удаляет данные. [Безопасность](SECURITY.md), [приёмка](VERIFICATION.md).
